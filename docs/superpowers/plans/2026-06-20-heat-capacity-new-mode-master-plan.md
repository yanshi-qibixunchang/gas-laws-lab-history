# 空气比热容比实验新模式与诊断系统总计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 用新的热容物理模型重新组织演示、引导、理论、真实四类实验模式，并在此基础上完成 UI 操作验收、小球可视化、记录流程、评分诊断和参数栏重构。

**Architecture:** 先建立可重复的 UI/模型验收骨架，再修正可视化和快速操作稳定性；之后拆分模式体系和持久化结构，最后重建诊断评分与右侧参数系统。所有模式都应共享同一套底层物理状态推进，不允许重新引入绕过 `stepFreePhysics` 的结果捷径。

**Tech Stack:** TypeScript, React/Vite, Three.js/R3F, Node `.test.ts`, Playwright or browser automation, `src/domain/heatCapacity`, `src/features/heatCapacity`, `src/features/workbench`.

## 2. 模式定义

### 2.1 教学流程类

- [ ] **演示模式：理想实验操作**
  - 自动执行标准理想操作。
  - 目标是展示实验流程和接近理论值的结果。
  - 使用理想实验操作参数组：18 下打气、12s 内完成、U1 等待 300s、放气 0.35s、U2 等待 300s。
  - 关闭漏气、环境扰动、传感器噪声、低压非线性和额外读数扰动。

- [ ] **引导模式：完全真实的合适实验操作**
  - 引导用户完成真实实验中合理的操作流程。
  - 使用真实默认参数组。
  - 保留热交换、弱漏气、传感器滞后、量化、噪声、低压非线性、泵阀交换和弱环境扰动。
  - 引导逻辑只约束流程和安全，不应把每个读数硬压到理论值。

### 2.2 自主实验类

- [ ] **理论模式：绝对理想情况**
  - 打气和放气可使用绝对理想过程。
  - 无漏气、无环境扰动、无传感器噪声、无读数扰动。
  - 允许调整少量底层理想参数，例如 `gamma`、气体量、容器体积、理论传感器比例等。
  - 不暴露会破坏“绝对理想”定义的真实误差参数。

- [ ] **真实模式：真实实操环境**
  - 不限制结果范围，只限制最基本操作流程和物理可记录前提。
  - 允许用户犯错，并记录错误造成的真实结果。
  - U0/U1/U2 必须按顺序记录。
  - U0 至少要求电源开、玻璃旋塞打开且实际流通。
  - U1 至少要求已有 U0。
  - U2 至少要求已有 U1 且发生过放气。
  - 错误操作不应被 UI 阻止，除非涉及安全阈值或物理上完全不可记录。

## 3. 新验收策略

### 3.1 自动化操作验收

- [ ] 建立内置浏览器或 Playwright 操作脚本，用于打开固定预览。
- [ ] 建立 DOM 级流程测试：模式切换、按钮点击、记录 U0/U1/U2、倍速等待、结果计算。
- [ ] 建立 3D 坐标点击冒烟测试：电源开关、玻璃旋塞、打气球、记录按钮。
- [ ] 为 3D 坐标测试固定初始视角和窗口尺寸。
- [ ] 添加失败截图或日志输出，便于定位点击偏移、遮挡或状态机异常。

### 3.2 快速点击和乱序操作验收

- [ ] 电源开关快速连点不会造成 `powerOn`、显示读数和物理状态不同步。
- [ ] 玻璃旋塞快速开关不会造成开阀动画、实际流通状态和物理放气状态错位。
- [ ] 打气阀快速开关不会绕过安全阈值或错误累计泵阀交换时间。
- [ ] 打气球快速点击不会丢失合法打气，也不会在报警后继续打气。
- [ ] U0/U1/U2 快速连点不会重复写入同一记录。
- [ ] 记录按钮乱序点击能被正确拒绝或记录为诊断事件，不会污染已完成记录。
- [ ] 倍速切换快速连点不会让物理时间倒退或跳过热交换/漏气计算。

### 3.3 模型验收矩阵

- [ ] 绝对理想情况：单次 gamma 四舍五入应接近 1.400。
- [ ] 理想实验操作：标准操作下 gamma 应进入理想实验容许区间。
- [ ] 完全真实最佳操作：固定 seed 多次运行均值应进入真实最佳区间。
- [ ] 合适真实操作：边界组合和随机抽样组合应进入真实合适区间。
- [ ] 单项错误操作：错误操作应产生可诊断的偏离或可靠度下降。
- [ ] 极端错误操作：极短放气、极长放气、过早记录等应产生明显错误表现。
- [ ] 新模式改造后，重新生成并保存基线结果文档。

## 5. 必须补充进计划的遗漏项

- [ ] **旧计划/旧断言清理**：旧计划可保留为历史资料，但与新模式定义冲突的断言必须迁移或删除。
- [ ] **存档兼容和版本迁移**：模式拆分后旧实验文件、旧 session、旧参数快照必须能打开。
- [ ] **随机性可复现**：所有噪声、环境扰动、传感器波动必须由 seed 或 trace 驱动，禁止在物理链路中直接使用不可复现随机数。
- [ ] **快速点击状态机**：电源、旋塞、打气阀、打气球、记录按钮、倍速都要有快速点击测试。
- [ ] **性能预算**：小球可视化、真实物理模型和 16x 倍速等待叠加时不能明显卡顿。
- [ ] **模式命名和入口 UI**：需要确定按钮分组、中文名称、英文名称和用户理解路径。
- [ ] **演示/引导自动流程参数**：演示和引导不能继续沿用含糊的旧流程，必须写明打气次数、等待时间、放气时间和扰动开关。
- [ ] **文献和建模说明更新**：模型体系变化后，GB 文献 md 和物理模型说明必须同步。
- [ ] **开发诊断输出**：需要受控开关输出 U1/U2/gamma、关键时间点、气体量、温度、漏气量、放气量和评分原因。
- [ ] **错误操作可视化**：错误操作不能只在分数里体现，过程图和诊断文字也要说明错误来源。
