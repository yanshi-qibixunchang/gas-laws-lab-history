# Advanced Heat Capacity Ratio Experiment Roadmap

## Purpose

This document records the follow-up plan for the advanced hard-sphere heat capacity ratio experiment. The experiment target remains a monatomic hard-sphere gas with theoretical heat capacity ratio `gamma = 5 / 3`.

The current implementation is the first working skeleton: it provides the experiment state machine, generated `p0 / p1 / p2 / gamma` readings, a procedural square pressure vessel, basic guided controls, and a model contract for later GLB replacement. The current particle display and 3D controls are intentionally not final.

## Batch 1: Completed Foundation

Status: implemented.

Current capabilities:

- Adds the `heatCapacity` file kind and creates files named `Heat Capacity Ratio - NNN`.
- Provides the macro thermodynamic experiment state machine:
  - `equalizing`
  - `pumping`
  - `stabilizingP1`
  - `recordP1`
  - `releasing`
  - `recovering`
  - `recordP2`
  - `completed`
- Generates and records `p0`, `p1`, and `p2` from guided experiment operations rather than manual input.
- Calculates `gamma`, theoretical `5 / 3`, and relative error.
- Uses a transparent square pressure vessel as the formal default container shape.
- Provides a procedural 3D skeleton with:
  - `Vessel`
  - `Valve_C1`
  - `Valve_C2`
  - `Pump_Handle`
  - `Pressure_Gauge_Needle`
  - `Temperature_Display`
  - `Hit_C1`
  - `Hit_C2`
  - `Hit_Pump`
- Keeps the current hard-sphere collision engine out of the primary `gamma` calculation path.
- Uses internal particles only as early visual placeholders.
- Defaults the right `Current Parameters` sidebar to collapsed for heat-capacity files.
- Gives the 3D preview more initial space than the realtime readings panel.

## Batch 2: Clear 3D Interaction Logic

Goal: make the experiment operation path obvious and reduce user confusion.

Planned work:

- Make the 3D model the primary operation surface over time, while keeping `Guided operations` as a clear fallback.
- Highlight only the parts that are valid for the current experiment phase.
- Add hover hints for model parts:
  - pump: pressurize the square vessel.
  - C1: inlet valve state.
  - C2: fast release valve.
  - pressure gauge: current pressure reading.
  - temperature display: current temperature state.
- Block invalid part interactions from advancing the state machine.
- Show a clear message when the user clicks the wrong part for the current phase.
- Add visible feedback after a valid click:
  - pump handle movement.
  - valve open or close state.
  - pressure and temperature changes.
  - stage progress update.
- Keep `p0 / p1 / p2` generated by experiment operations, not by direct main-flow manual input.
- Rename or visually reposition the realtime panel later if needed so it reads as an experiment readings board rather than a chart-first surface.

Acceptance criteria:

- A first-time user can identify the next valid 3D part to operate without reading code or external instructions.
- Invalid interactions do not change recorded experiment data.
- The button flow and 3D part flow drive the same state machine and cannot diverge.

## Batch 3: Particle Teaching Animation

Goal: make particles visually match the macro thermodynamic state without using them as the source of `gamma`.

Planned work:

- Keep the macro state machine as the only source for `p0 / p1 / p2 / gamma`.
- Animate particles as teaching visualization:
  - `pumping`: density visually increases, particle speeds increase, color shifts warmer.
  - `stabilizingP1`: particle speeds cool back toward ambient temperature while density stays elevated.
  - `recordP1`: particles appear stable at high pressure and ambient temperature.
  - `releasing`: some particles stream out through C2, density decreases, color shifts cooler.
  - `recovering`: particle speeds return toward ambient temperature.
  - `recordP2` and `completed`: particles stabilize at the final state.
- Use a lightweight animation model first.
- Do not use the existing hard-sphere particle collision engine as the primary calculation source.
- Optionally add a later advanced visualization mode that reuses hard-sphere collision concepts for display only.

Acceptance criteria:

- Particle density, speed, and color consistently reinforce the current pressure and temperature state.
- The animation never changes the recorded `p0 / p1 / p2 / gamma` values directly.
- The visual state remains stable after experiment completion.

## Batch 4: Automatic Teaching Demonstration

Goal: repurpose the top green run button for heat-capacity files so it becomes a controlled teaching demonstration instead of a normal simulation run control.

Planned work:

- For `heatCapacity` files, the green run button should start an automatic full experiment demonstration.
- On first open of this experiment type, show a guide prompt inviting the user to watch the demonstration.
- The demonstration automatically performs:
  - record `p0`.
  - pump.
  - stabilize and record `p1`.
  - fast release.
  - recover.
  - record `p2`.
  - calculate and explain `gamma`.
- During the demonstration, show explanatory prompts and synchronize them with model highlights, particle animation, and readings.
- After the demonstration finishes, hide or disable the green run button for that file to avoid accidental replay.
- Tell the user they can create a new heat-capacity experiment file to watch the demonstration again.
- Prevent the automatic demonstration from running in the middle of a manual experiment.

Acceptance criteria:

- The top run button no longer feels like a standard simulation start control for this experiment.
- A completed demonstration cannot corrupt a later manual experiment in the same file.
- The user has a clear path to replay by creating a fresh heat-capacity file.

## Batch 5: Realistic GLB Instrument Replacement

Goal: replace the simple procedural model with a more realistic 3D instrument while preserving the existing state machine and model contract.

Core rule:

The procedural model is the skeleton. The GLB model is the appearance. The GLB must not introduce a second experiment logic system.

Planned work:

- Produce a model specification before building the GLB:
  - square transparent pressure chamber dimensions.
  - valve locations.
  - pump handle location and travel direction.
  - pressure gauge location and needle pivot.
  - temperature display location.
  - internal pressure sensor location inside or attached to the square vessel.
  - internal temperature sensor probe location inside the square vessel.
  - sensor wiring or signal leads from the vessel to an external instrument box.
  - external instrument box placement, screen area, controls, and cable sockets.
  - hitbox positions and sizes.
- Require stable node names in the GLB:
  - `Vessel`
  - `Valve_C1`
  - `Valve_C2`
  - `Pump_Handle`
  - `Pressure_Gauge_Needle`
  - `Temperature_Display`
  - `Pressure_Sensor`
  - `Temperature_Sensor`
  - `Sensor_Cable_Pressure`
  - `Sensor_Cable_Temperature`
  - `Instrument_Box`
  - `Instrument_Box_Display`
  - `Hit_C1`
  - `Hit_C2`
  - `Hit_Pump`
  - `Hit_Instrument_Box`
- Keep the same state inputs for both procedural and GLB models:
  - valve open or closed states.
  - pump progress.
  - pressure.
  - temperature.
  - experiment phase.
  - highlighted or active part.
- Add a GLB loader path with fallback:
  - use GLB when loading succeeds.
  - fall back to the procedural skeleton when loading fails.
- Drive model animation from state:
  - valve rotation or open-state indicator.
  - pump handle travel.
  - pressure gauge needle rotation.
  - temperature display value.
  - internal sensor indicator states.
  - instrument box display values for pressure, temperature, phase, and measured `gamma` when available.
  - part highlight and hitbox response.
- Keep the internal particle visualization inside the square vessel.
- The external instrument box should be a real 3D object in the scene, not only a flat UI panel.
- The external instrument box display must read from the same experiment state as the 2D readings panel, so it stays synchronized with `p0 / p1 / p2`, pressure, temperature, phase, and final `gamma`.
- Sensor cables should make the measurement chain visually explicit: vessel sensor -> cable -> instrument box -> live display.

Acceptance criteria:

- Replacing the model does not require changing experiment calculation code.
- Procedural and GLB models can be swapped using the same state interface.
- GLB pivots and hitboxes match the procedural skeleton closely enough that existing interactions still work.
- Failure to load the GLB does not break the experiment.
- Internal sensors and the external instrument box are visible enough for users to understand where pressure and temperature readings come from.
- The instrument box display updates in sync with the experiment state and never becomes a separate source of truth.

## Batch 6: Experiment Completion And Polish

Goal: make the feature suitable as a complete advanced teaching experiment.

Planned work:

- Localize user-facing heat-capacity text consistently.
- Add concise step purpose text:
  - why record `p0`.
  - why pump and stabilize before `p1`.
  - why release quickly.
  - why recover before `p2`.
  - how `gamma` is calculated.
- Improve the result summary:
  - `p0`.
  - `p1`.
  - `p2`.
  - measured `gamma`.
  - theoretical `5 / 3`.
  - relative error.
  - operation quality or likely error source.
- Add repeated trials:
  - per-trial result.
  - average `gamma`.
  - average relative error.
- Add guided error feedback:
  - release too short.
  - release too long.
  - delayed valve closing.
  - recording before stabilization.
- Explain the measurement chain in user-facing guidance:
  - pressure sensor measures vessel pressure.
  - temperature sensor measures gas temperature.
  - external instrument box displays live sensor data and recorded values.
- Reserve advanced manual data entry mode for late-stage expert use only.
- Keep manual entry separate from the main guided experiment path.
- Add browser visual checks for desktop and narrower viewports.

Acceptance criteria:

- A user can complete one guided experiment without external instructions.
- The result panel explains both measured and theoretical values.
- Repeated measurements can be reviewed without confusing them with the current active run.
- The feature remains compatible with the procedural fallback and the GLB model.

## Recommended Order

Implementation should proceed in this order:

1. Batch 2: clear 3D interaction logic.
2. Batch 3: particle teaching animation.
3. Batch 4: automatic teaching demonstration.
4. Batch 5: realistic GLB model replacement.
5. Batch 6: final experiment polish.

The GLB replacement should not be implemented before the interaction and animation contracts are stable. Building the model too early risks mismatch between the realistic appearance and the working experiment skeleton.

## Long-Term Notes

- The square pressure vessel remains the official default shape.
- The experiment represents monatomic hard-sphere gas, not air.
- The theoretical target remains `gamma = 5 / 3`.
- The main experiment flow should not expose direct `p0 / p1 / p2` manual input.
- A manual data-entry mode can be added later as an advanced mode, isolated from guided operation.
- The existing hard-sphere collision engine can inspire the visualization, but it should not become the primary source of the measured heat capacity ratio.
