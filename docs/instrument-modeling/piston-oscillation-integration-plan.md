# 活塞振动法当前开发路线图

## 文档用途

- 本文是活塞振动法实验模式的唯一现行开发路线图，只描述当前实现和后续顺序。
- 已确认的实验操作、物理状态、采集内容和计算关系以 `piston-oscillation-experiment-spec.md` 为准。
- 已完成的设计迭代不在本文保留；需要追溯时使用 Git 历史，不在现行文档中混放旧方案。

## 当前实现基础

- 活塞振动法使用独立文件类型 `kind: 'heatCapacityPistonOscillation'`，不进入 standard、ideal 或绝热膨胀法运行时。
- 正式仪器资产唯一为 `public/models/piston-oscillation/piston-oscillation.glb`；模型来源、哈希、关键节点和加载失败路径均有合同测试。
- 正式工作区包含仪器交互、压力采集、曲线周期处理、拟合计算、结果、保存和恢复闭环。
- 物理状态、传感器观测、派生结果和交互会话相互分离；Three.js 运行时对象不得写入实验持久化数据。
- 多文件不得共享会被修改的场景实例；切换文件和卸载时必须停止组件拥有的动画并释放对应资源。

## 唯一数据链路

正式采集只使用以下链路：

`用户释放活塞 → 版本化物理模型轨迹 → 1000 Hz 传感器观测 → 下降沿触发 → 正式记录样本 → 周期选择与拟合 → γ 与误差结果`

- 同一次释放的仪器动画、压力采集和物理快照必须共用同一条轨迹与同一时间原点。
- 正式观测采用 `1000 Hz` 离散时间和 `0.01 kPa` 向零截断；图表、触发、极值、端点和计算只读取正式观测样本。
- 工作流测试使用固定观测记录；科学结果测试绑定明确的物理模型版本。
- 产品运行时不保留独立的预置波形、合成正弦曲线或缺少物理轨迹时的替代数据源。
- 零损耗绝热模型仅用于后台不变量测试，不构成第二套产品模型。

## 当前物理模型边界

- 软件空气的版本化客观物性为 `γ = 1.40`；状态方程、原始测量物理快照和相对误差共用同一来源。
- 当前引导模式固定使用本机铭牌运动质量 `48.5 g ± 0.6 g`、活塞直径 `32.5 mm ± 0.1 mm`，以及包含气缸、软管、接口和传感器腔体的有效气体体积。
- `0.434 N·s/m` 是维持当前已验收引导曲线的版本化临时等效损耗，不解释为真实机械摩擦或热力学阻尼。
- 热交换、熵变化、机械摩擦、软管动态响应、传感器噪声、平台效应和次峰尚未成为正式产品模型，不得通过平行分支提前接入。

## 当前唯一实施顺序

1. **固定正确操作基线**：先冻结正确操作的时序、记录长度、周期选区和结果验收锚点。当前结论记录在 `piston-oscillation-correct-operation-baseline.md`；真实四组数据只约束波形量级和选区习惯，不反向充当全部物理参数的真值。
2. **建立自由模式骨架**：引入动态 experiment plan、`3–6` 组 Run、高度设置、返回、重做、删除、重新框选、动态拟合、完整保存恢复、非阻断操作、原始事件记录、统一评价器和过程回顾。进入窗口固定使用“次数输入/下拉选择 + 等量正式高度按钮框选”两步结构；首次默认 `3` 次和 `80、70、60 mm`，确认前允许改为任意 `3–6` 个正式高度。用户的错误操作不弹出步骤错误提示，也不被强行纠正；系统只让物理后果进入实验进程和结果，并在回顾阶段评价。
3. **接入释放扰动与第一版摩擦模型**：先记录左右手释放顺序和时间差，形成一个可版本化的“释放扰动状态”；第一版只让摩擦模型读取该状态。正确同步释放的新增扰动应接近零，避免新模型破坏步骤一的正确基线。
4. **完成错误点矩阵**：分别验证 `0、1、2、3` 个错误 Run，并覆盖错误点位于低、中、高高度的情况。逐项检查能否继续、曲线是否可用、周期是否可选、拟合斜率和截距如何变化、`R²` 与最终 `γ` 偏差是否符合严重程度。
5. **逐个补充其他真实机制**：在释放摩擦闭环后，再依次加入释放倾斜或其他有证据的扰动、环境影响、传感器响应与噪声、用户观测偏差。每次只引入一个可解释机制，不用总扰动系数同时代替多个未知原因。
6. **联合校准与变量开放**：各单项机制都有独立证据、参数来源和回归测试后，再做联合参数校准；只把具有教学意义、因果关系清楚且结果可解释的变量开放给自由模式用户。

## 每增加一个模型的固定小闭环

1. 收集直接证据，写清该机制的因果链、适用范围和未知项。
2. 定义输入、内部状态、输出、参数单位、默认值、允许范围、随机种子和模型版本；不能只保留一个无法解释的“坏曲线程度”。
3. 先跑正确操作基线，确认新机制在正确条件下不会把周期、衰减、拟合和 `γ` 推出当前合理范围。
4. 再跑该机制的错误情景矩阵，区分“无法继续”“仍可处理但数据较差”“可完成却得到偏差结果”三类后果。
5. 分别检查一个、两个、三个错误点以及错误点在拟合区间不同位置时的影响；不得只验证一条坏曲线。
6. 将参数来源、场景输入、观测样本、结果和评分事件一起保存，并补齐确定性测试、持久化恢复和版本迁移。
7. 通过人工验收后才进入下一个机制；后续联合校准不能删除单项模型的独立回归锚点。

## 阶段门禁

- 每个阶段必须先通过类型检查、自动测试、持久化恢复检查和人工验收，再进入下一阶段。
- 交互、物理模型、数据结构或持久化格式发生变化时，同一改动必须同步更新测试和现行文档。
- 保存格式升级必须保留明确的版本迁移路径；兼容代码只承担已有数据升级，不得成为运行时第二套业务方案。
- 正确操作基线已于 `2026-08-27` 由用户确认，当前允许进入自由模式骨架；在自由模式数据链和恢复闭环验收前，不接入真实耗散、传感器噪声或其他扩展模型。

## 当前下一步

步骤二的下一实施批次只闭合正式高度 Run 的采集链，不提前接入自定义高度、摩擦或其他真实扰动：

1. 将所选高度计划接入 A 幕，提供当前 Run/总数/目标高度与逐项状态的动态进度组件。
2. 统一采样频率和触发阈值的键盘输入、提交、锁定与 Run 设置快照；范围内错误值允许进入实验，超出仪器能力的配置不能启动采集。
3. 完成“等待触发 → 正式记录 → 停止并冻结 → 保存正式 Run → 进入下一目标高度”的原始曲线闭环。
4. 落实四个彼此独立的动作：退出并恢复会话、重做当前候选、删除已保存 Run 后重采、放弃整轮并重新选择计划；删除和重做只改变活动数据，排除证据继续用于撤销、恢复和过程评价。
5. 所选高度全部保存后再进入自由模式的数据处理；正式停止方式和完成采集后的切换方式在实施前确认，不在代码中并存多个临时方案。

以上闭环通过类型、自动测试、保存恢复和人工验收后，再加入不限数量的自定义候选高度及可滚动选择区；随后才进入左右手释放时间差与第一版瞬态摩擦模型。
