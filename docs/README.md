# 文档地图与维护规则

> 状态：当前文档入口
> 适用版本：6.4.0 及其后的未发布开发版本
> 最后核验：2026-09-14

本文件是仓库非代码材料的统一入口。阅读或修改资料时，先判断文档状态，再决定它能否作为当前实现依据。

## 依据优先级

出现冲突时，按以下顺序判断：

1. 当前代码、自动化测试和生成型法律清单决定软件实际行为。
2. 标记为“当前规范”或“当前合同”的文档解释设计边界。
3. 各实验的 `references/` 和 `docs/theory/` 提供理论、仪器和第三方依据，不直接替代实现合同。
4. `ideas/improvement-ideas.md` 记录仍有效但尚未实施或尚待决策的事项。
5. `archive/` 只保存历史背景和审计证据，不得作为当前待办或实现入口。

## 状态写法

新增或大幅修订的重要文档，开头应尽量包含：

```text
状态：当前规范 / 当前参考 / 待复核 / 未来设想 / 历史归档 / 第三方原始资料
适用版本：明确版本或版本范围
最后核验：YYYY-MM-DD
替代关系：如有，写明替代或被替代的文档
```

## 来源记录规则

- 项目自行制作的代码、文档、模型或图像标记为“本项目原创”或“项目内部制作”，不虚构第三方来源。
- 原创成果若依据论文、仪器说明或照片制作，应分别记录“成果权利状态”和“参考依据”。
- 第三方原始文件应保留作者、标题、取得位置、用途、许可证或合理使用边界；原始文件自身的排版或交叉引用错误只做旁注，不直接改写原件。
- npm、字体、Electron、Chromium、导出器等精确版本和许可，以自动生成的 `public/legal/` 清单及根目录 `THIRD_PARTY_NOTICES.md` 为准。

## 待办和归档规则

- 当前有效事项只写入 `docs/ideas/improvement-ideas.md` 或正式任务系统。
- 归档文档中的未勾选复选框是历史现场，不代表当前仍需实施。
- 归档前先提炼仍有效的设计约束、测试矩阵和未来想法。
- 当前文档不得依赖本机绝对路径；命令示例优先使用仓库相对路径。
- `release/` 是桌面发布资产，不按普通缓存清理；可再生成的 `dist/`、`output/`、`tmp/` 和浏览器测试缓存可在核实后清理。
