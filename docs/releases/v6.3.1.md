# v6.3.1

发布日期：2026-08-30

6.3.1 是活塞振动法的自由模式数据质量与交互节奏补丁。在 6.3.0 已建立的连续热—传感—按压采集链上，本版补齐不可用记录自动重做、自由模式统一校验、尾段不规则观测、双手松手差异和版本化统一损耗，同时修复未触发记录后无法再次实时监测的问题。

## 简体中文发布说明

### 数据质量与处理流程

- 软件会区分“整条记录不足半个可信主周期”和“曲线可用但用户框选太窄”。前者保留过程证据并只自动重做当前 Run；后者只要求重新框选，不会退回仪器。
- 自动重做会断开软管、将活塞复位到 `0 mm`、完全松开锁紧螺钉，同时保留电源、采样率、触发阈值、目标高度和其他已完成 Run。
- 自由模式每条曲线的 `t₁、t₂、T` 改为填写完成后统一校验；拟合后的 `A、γ、相对误差` 同样统一校验。校验前可以返回修改，格式无效的草稿不会被记作正式错误尝试。
- 数据处理主界面继续保留演示、引导、自由和退出控件；二级计算窗口打开时锁定这些控件，避免破坏正在进行的计算。

### 波形、手感与显示

- 新实验加入按实验种子生成的尾段不规则观测：后段少量局部时间折叠和峰谷肩部削弱会增加周期框选考量，同一实验保存和重启后逐点保持一致。前段主体波形、`1000 Hz` 时间网格和底层热—力学轨迹不变。
- 对四组实测曲线和 256 组固定种子软件实验的同口径比较表明，尾段框选造成的额外 `γ` 误差中位数为 `4.05` 个百分点，实测为 `4.89` 个百分点；该层只作为有边界的观测模型，不宣称已经唯一识别真实物理成因，也不保证每条随机曲线尾段都必然更差。
- 新建实验的虚拟手按压与自由振动统一使用版本化 `1.1 N·s/m` 等效线性损耗。该值表示当前聚合耗散，不等同于单一实物摩擦系数；旧存档仍按保存的 `0.434 N·s/m` 或其他受支持快照恢复。
- 左右手松手时间差超过中性区后，会产生随约一个自然周期指数衰减的短时侧向接触损耗，影响初段振幅和衰减；单手先松不会让平台被错误地立即上抬，也不会改变气体刚度或加入永久摩擦。
- 正式曲线增加 `0.300 s` 呈现延迟，并以受限 `30 fps` 增量连续揭示；前 `0.400 s` 物理曲线按 `0.55` 倍节奏显示，随后无跳跃恢复正常推进。该节奏只影响 UI，不改变采样率、时间戳、保存曲线、周期或计算结果。

### 修复

- 一次按压没有越过下降触发线时，运动与音效结束后会重新绑定实时传感器会话。自由模式和引导模式均可直接再次按压，监测点与音效继续响应，无需暂停、重做或重新进入模式。
- 计算窗口按钮按文案自然扩展，“统一校验三项结果”等较长文字不再被固定宽度截断或溢出。

### 兼容性

- 可从 `v6.3.0` 直接覆盖更新；应用 ID、安装身份、公开更新仓库和用户资料目录不变。
- 已保存原始曲线不会因新尾段模型重新生成，旧损耗、旧传感器和已有处理结果继续按其保存快照恢复。
- 本版不新增独立摩擦、软管传递、泄漏、环境扰动、评分或过程回顾模型。

## 繁體中文發佈說明

### 資料品質與處理流程

- 軟體會區分「整條記錄不足半個可信主週期」和「曲線可用但使用者框選太窄」。前者保留過程證據並只自動重做目前 Run；後者只要求重新框選，不會退回儀器。
- 自動重做會斷開軟管、將活塞復位到 `0 mm`、完全鬆開鎖緊螺釘，同時保留電源、取樣率、觸發閾值、目標高度和其他已完成 Run。
- 自由模式每條曲線的 `t₁、t₂、T` 改為填寫完成後統一校驗；擬合後的 `A、γ、相對誤差` 同樣統一校驗。校驗前可以返回修改，格式無效的草稿不會被記作正式錯誤嘗試。
- 資料處理主介面繼續保留演示、引導、自由和退出控制項；二級計算視窗開啟時鎖定這些控制項，避免破壞正在進行的計算。

### 波形、手感與顯示

- 新實驗加入依實驗種子產生的尾段不規則觀測：後段少量局部時間摺疊和峰谷肩部削弱會增加週期框選考量，同一實驗儲存和重新啟動後逐點維持一致。前段主體波形、`1000 Hz` 時間網格和底層熱—力學軌跡不變。
- 新建實驗的虛擬手按壓與自由振動統一使用版本化 `1.1 N·s/m` 等效線性損耗；舊存檔仍依儲存的 `0.434 N·s/m` 或其他受支援快照還原。
- 左右手放手時間差超過中性區後，會產生隨約一個自然週期指數衰減的短時側向接觸損耗，影響初段振幅和衰減；單手先放不會讓平臺被錯誤地立即上抬，也不會改變氣體剛度或加入永久摩擦。
- 正式曲線增加 `0.300 s` 呈現延遲，並以前 `0.400 s` 物理曲線 `0.55` 倍節奏連續顯示。該節奏只影響 UI，不改變取樣、時間戳、儲存曲線、週期或計算結果。

### 修正與相容性

- 一次按壓沒有越過下降觸發線時，自由模式和引導模式都可在運動結束後直接再次按壓，監測點與音效會繼續回應。
- 計算視窗按鈕會依文字自然擴展，不再截斷統一校驗文案。
- 可從 `v6.3.0` 原地更新；舊曲線、舊損耗和舊感測器快照不會被重新解釋或改寫。

## English release notes

### Data quality and processing

- Free Mode distinguishes a whole recording with no credible primary half-cycle from a usable recording with a selection that is merely too narrow. Only the former reacquires the current run, preserving evidence, settings, and other completed runs.
- Each curve now validates `t1`, `t2`, and `T` together. The fitted `A`, `gamma`, and relative error also validate as one batch. Users may revise visible fields before checking, and malformed drafts do not count as formal errors.
- Demo, Guide, Free, and exit controls remain available on the main processing view and lock only while the secondary calculation window is active.

### Waveform, interaction, and presentation

- Seeded tail observations add sparse local time folds and shoulder attenuation late in new sensor traces. Saved traces replay sample-for-sample while the early waveform, `1000 Hz` grid, and underlying thermomechanical trajectory remain unchanged.
- New experiments use one versioned `1.1 N·s/m` equivalent linear loss for virtual-hand pressing and free oscillation. Historical saves continue to use their captured `0.434 N·s/m` or other supported snapshot.
- Unequal hand-release timing can produce a short-lived side-contact loss that decays over roughly one natural period without lifting the platform after one hand releases, changing gas stiffness, or adding permanent friction.
- The chart uses a `0.300 s` presentation delay with capped `30 fps` advances. The first `0.400 s` of physical trace is presented at `0.55x`; sampling, timestamps, saved data, periods, and calculations remain unchanged.

### Fixes and compatibility

- Live monitoring and audio recover after a press that never crosses the falling trigger, allowing an immediate retry in Free and Guide modes.
- Calculation actions expand to fit longer unified-validation labels.
- Version `6.3.0` can update in place. Existing traces, loss snapshots, sensor snapshots, processing results, application identity, and the user-data directory remain intact.
