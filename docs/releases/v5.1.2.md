# v5.1.2

发布日期：2026-07-18

5.1.2 是基于 5.1.1 的稳定性更新，重点完善工作区保存与恢复、实验身份、Free／Guide／Demo 三模式状态一致性、运行时恢复、桌面更新自救及三语言气律实验室品牌。

## 重要升级说明

- 正常运行的 5.1.1 可以通过应用内“检查更新”升级到 5.1.2；如果 5.1.1 已停留在只读持久化故障页，请从受信任的发布页下载 5.1.2 安装器并直接覆盖安装。
- 不要卸载 5.1.1，也不要清除 `<local-user>\AppData\Roaming\hard-sphere-lab`。5.1.2 会继续使用该原资料目录并严格迁移保存内容。
- 覆盖安装复用原 appId、NSIS 升级身份、安装目录、快捷方式和用户资料目录，不会正常产生第二份应用；为进一步降低运行中写入风险，手动安装前建议先关闭应用，安装器也会等待完整的安全保存窗口。
- 5.1.2 的只读故障页新增检查、下载、重启安装和受信任的最新发布页入口；旧 5.1.1 的故障页本身无法反向获得这些按钮，因此首次修复需要手动覆盖安装。

## 工作区保存与恢复

- 补齐 4.2.3 工作区和 5.1.1 空白会话所需的 Free、Guide、Demo 固定参数、传感器、旋塞计时、历史 U1 等待锚点及模式投影迁移。合法旧资料会被精确规范化，真正损坏的当前格式仍保持严格拒绝。
- 将用户可见的 001、002 实验编号与内部持久化 ID 分离。永久删除任意或全部实验后重新新建会获得全新且不复用的内部 ID，并立即生成 Free、Guide、Demo 三条模式记录；普通保存仅在事务提交后严格回读文件、模式记录和 revision 全部一致时才报告成功。
- 保存失败会保留既有资料并阻止静默退出，不会因为校验失败自动清空数据库，也不使用“清数据后能打开”或宽松 fallback 作为恢复方式。

## 实验运行稳定性

- Free、Guide、Demo 切换会在新场景真正就绪后恢复对应运行状态；错误、退出和刷新恢复期间暂停提醒与实时 tick，避免后台计时继续推进。
- 真实 WebGL 上下文丢失会进入统一冻结、错误卡与重试路径；场景连续两帧就绪后才恢复运行。
- 统一运行时间和显示值的边界舍入口径，避免正常实验在特定时间点被错误判定为不可保存。

## 桌面更新与恢复

- 持久化初始化失败时不再启动临时命名空间清理；只读故障页保留无边框桌面的最小化、最大化和安全关闭按钮，并正确响应更新安装前的保存协调，避免重启安装等待超时。
- 自动检查尚未取得版本信息时，手动更新入口会回退到由内置发布目标生成并经过同一严格白名单验证的 GitHub 最新发布页。
- 覆盖安装继续复用原 appId、NSIS 安装身份、安装目录、更新仓库和用户资料目录，不会正常生成第二份应用或迁移到新的资料位置。

## 品牌与图标

- 应用内名称按界面语言显示为“气律实验室”“氣律實驗室”或 “Gas Laws Lab”，语言切换会同步标题栏、关于页、帮助与更新界面，重启后继续使用已保存语言。
- Windows 安装器、快捷方式、卸载项和可执行文件使用稳定系统级名称 “Gas Laws Lab”。单个 Windows 安装包无法随应用内语言偏好动态重命名这些外壳项目。
- 使用新的 γ 循环箭头图标，并为 Windows 生成 16、24、32、48、64、128、256 像素 ICO 帧及完整网页 PNG 尺寸。
- 保持 `hard-sphere-lab` 包身份、`com.hardspherelab.desktop` appId、安装升级身份、公开更新仓库、更新缓存和原用户资料目录不变。

## 桌面更新资产

本次公开稳定更新必须同时发布以下三个文件：

- `heat-capacity-lab-setup-5.1.2.exe`
- `heat-capacity-lab-setup-5.1.2.exe.blockmap`
- `latest.yml`

`latest.yml` 中的安装器文件名、版本、SHA-512、下载地址与发布资产必须完全一致；不得覆盖或替换 5.1.1 的历史资产。
