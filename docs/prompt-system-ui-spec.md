# 软件提示体系 UI 规范（B 方案）

状态：已由用户于 2026-07-22 选定，并完成正式接入。  
适用范围：内部确认、告知、任务窗口外壳、Toast、持续警报、Tooltip、行内二次确认及教学/过程提示的共享视觉语义。  
原则：保持当前软件简洁、紧凑、克制、精确的桌面工程软件风格；本规范不改变任何实验业务规则。

## 1. 视觉方向

B 方案保持现有工作台的信息密度，在不扩大窗口体量的前提下加强三类层级：

1. 标题区：状态图标、状态眉题和主标题形成稳定识别区；
2. 内容区：主要说明与后果说明分层，后果说明使用细状态竖线；
3. 操作区：取消保持中性，主要操作根据普通、警告或危险语义着色。

禁止玻璃拟态、模糊背景、渐变、霓虹、大圆角、重阴影、营销式大标题、Emoji 功能图标和大面积危险色。

## 2. 公共设计变量

正式组件统一使用 `--prompt-*` 变量；变量定义集中在提示组件公共样式中，并优先映射现有 `--studio-*` 主题变量。

### 2.1 字体与字号

| 变量 | 值 | 用途 |
| --- | --- | --- |
| `--prompt-font-ui` | `var(--app-font-ui)` | 标题、正文、按钮 |
| `--prompt-font-data` | `var(--app-font-data)` | 状态眉题、工程标签 |
| `--prompt-type-eyebrow` | `9px` | 状态眉题 |
| `--prompt-type-button` | `10px` | 按钮与后果说明 |
| `--prompt-type-body` | `12px` | 正文 |
| `--prompt-type-title` | `14px` | 窗口主标题 |

正文行高为 `1.5`，标题行高为 `1.3`。标题、正文和按钮不得使用新的字体家族。

### 2.2 间距

| 变量 | 值 |
| --- | --- |
| `--prompt-space-1` | `4px` |
| `--prompt-space-2` | `8px` |
| `--prompt-space-3` | `12px` |
| `--prompt-space-4` | `14px` |

窗口标题区高度最小 `48px`；内容区内边距 `14px`；操作区上下内边距 `9px`、左右 `14px`；按钮间距 `8px`。

### 2.3 圆角、边框与阴影

- 控件圆角：`4px`；
- 窗口圆角：`5px`；
- 窗口外边框：`1px solid var(--prompt-border)`；
- 标题区与操作区分隔线：`1px solid var(--prompt-border-soft)`；
- 状态竖线：`3px`；
- 深色窗口阴影：`0 20px 46px rgba(0, 0, 0, 0.36)`；
- 浅色窗口阴影：`0 20px 48px rgba(32, 40, 48, 0.24)`。

阴影只用于需要建立模态层级的窗口；普通面板和行内提示不得复制该阴影。

### 2.4 遮罩

- 深色：`rgba(7, 10, 14, 0.68)`；
- 浅色：`rgba(32, 40, 48, 0.38)`；
- 遮罩覆盖整个软件客户区，阻止背景鼠标和键盘交互；
- 可关闭窗口点击遮罩等同取消；强制告知点击遮罩无效。

## 3. 状态颜色

- 普通信息：使用现有蓝色主色；
- 成功：使用现有绿色，只出现在图标、细边框或局部标签；
- 警告：使用现有克制的赭黄/橙色；
- 危险：使用现有低饱和红色；
- 危险色和警告色不得大面积铺满正文或整个窗口；
- 状态色主要用于左侧 `3px` 竖线、图标容器、眉题和最终操作按钮。

## 4. 确认窗口

统一结构为：状态图标、眉题、标题、主要说明、后果说明、取消、确认。

### 4.1 普通确认

- 用于可逆、低风险但仍需要用户明确决定的操作；
- 主操作使用蓝色；
- 默认焦点仍放在取消按钮。

### 4.2 警告确认

- 用于会重置进度、停止运行或改变当前流程的操作；
- 使用警告色图标、状态竖线和主操作按钮；
- 取消按钮保持中性；
- 当前阶段的“重置未完成组”“切换并重置教学进度”“关闭运行中的实验文件”均属于警告确认。

### 4.3 危险确认

- 只用于不可撤销删除或同等级破坏性操作；
- 红色只用于危险识别和最终危险按钮；
- 不得默认聚焦危险按钮。

### 4.4 交互规则

- 打开后默认聚焦取消；
- 右上角关闭按钮等同取消；
- `Esc` 等同取消；
- 点击遮罩等同取消；
- `Tab` 与 `Shift+Tab` 将焦点限制在当前窗口；
- 关闭后焦点返回触发控件；
- 当前窗口未处理完时拒绝第二次确认请求；
- 一次确认只能执行一次回调，双击不得重复提交；
- 确认窗口打开时背景不可交互。

## 5. 普通告知与强制告知

### 5.1 普通告知

- 可以根据场景提供确认按钮、右上角关闭、`Esc` 和遮罩关闭；
- 不要求用户作业务决定，只确认信息已阅读或任务已完成。

### 5.2 强制告知

- 不显示右上角关闭；
- `Esc` 无效；
- 点击遮罩无效；
- 必须完成明确指定操作才能关闭；
- 与普通告知共享标题、内容、按钮、遮罩、焦点和主题变量。

## 6. 大型任务窗口外壳

- 更新、计算、设置、关于和参数窗口共享标题栏、边框、遮罩、阴影、基础间距和焦点规则；
- 不强制统一窗口尺寸；
- 不强制统一内部布局；
- 任务进行中的不可关闭规则由各业务流程决定。

## 7. 按钮规则

- 按钮最小高度 `30px`，左右内边距 `12px`；
- 取消位于左侧，确认位于右侧；
- 取消按钮使用中性色；
- 普通确认使用蓝色主按钮；
- 警告确认使用赭黄主按钮；
- 危险确认使用低饱和红色主按钮；
- `hover` 只加深背景；
- `active` 加深背景并下移 `1px`；
- `disabled` 降低对比度且不响应指针；
- 键盘焦点使用 `2px` 清晰外轮廓和 `2px` 偏移。

## 8. 图标规则

- 使用项目现有 Lucide 图标库；
- 普通确认使用问号圆形图标；
- 警告确认使用三角警告图标；
- 危险确认使用与动作相符的危险图标；
- 图标默认 `17px`、`1.9` 描边；
- 图标容器为 `30px × 30px`；
- 禁止 Emoji、文字字符和手工 SVG 代替功能图标。

## 9. 动画

- 快速控件状态：`120ms`；
- 窗口和遮罩进入：`170ms`；
- 缓动：`cubic-bezier(0.2, 0, 0, 1)`；
- 遮罩只淡入；窗口淡入并从下方移动 `5px`；
- 不使用弹跳、缩放或持续装饰动画；
- 检测到 `prefers-reduced-motion: reduce` 时，将非必要动画和过渡缩短为 `1ms`。

## 10. Toast、持续警报与教学提示边界

- Toast 只承载短时结果或状态，不承载需要用户决定的内容；
- 成功、信息、警告、危险 Toast 共享字体、状态色、图标、边框和动画变量；
- 全局 Toast 固定在客户区右上角，宽度不超过 `360px`，按危险、警告、信息、成功排序，最多同时显示 4 条；
- 短时、标准和延长显示策略分别为 `2000ms`、`2600ms` 和 `6200ms`；持续状态不启用自动关闭计时；
- Toast 堆栈空白区域不拦截指针，单条可关闭 Toast 提供本地化关闭按钮和可见键盘焦点；
- 危险 Toast 使用 `role="alert"` / `aria-live="assertive"`，其余使用 `role="status"` / `aria-live="polite"`；
- 扫描输入错误、关于页操作结果以及工作区保存重试/失败共用一个堆栈；保存状态使用稳定 ID 更新，不重复叠加同一故障；
- 压强超限保持视图区内持续警报，不自动消失、不进入 Toast 队列、不阻断整个软件；
- 压强警报、教学完成和引导反馈使用实色紧凑表面，不使用大面积红色、玻璃模糊或正方形警报卡；
- 教学遮罩、控件高亮、预热和等待计时保持独立形态，只共享字体、状态色、层级、实色表面和动画语义。

## 11. Tooltip

- 同时支持鼠标悬停和键盘聚焦；
- 鼠标悬停延迟 `420ms`，键盘聚焦延迟 `120ms`，离开/失焦延迟 `80ms`；`Esc` 立即关闭；
- 支持屏幕边缘避让、最大宽度和长文案换行；
- 显示时通过 `aria-describedby` 关联，关闭后恢复控件原有描述；不删除触发控件原有的 `aria-label` 等无障碍名称；
- 通用入口使用事件委托，并将后续动态挂载的普通 DOM `title` 提升为内部 Tooltip，避免重新出现宿主原生提示；
- `iframe title` 是嵌入内容的无障碍名称，不属于悬停提示，必须保留且不参与提升；
- Tooltip 最大宽度 `280px`，自动在控件上下方翻转并在视口四边保留至少 `8px`；
- Tooltip 不得遮挡当前关键操作。

## 12. 行内二次确认

- 第一次点击进入确认状态；
- 第二次点击才执行；
- 点击外部、按 `Esc` 或点击取消后退出；
- 不再追加第二层确认窗口；
- 删除记录、删除数据点、清空关系、删除实验文件和重启批次继续使用此形态。

## 13. 浅色与深色主题

- 两种主题共享字号、间距、圆角、结构和交互；
- 颜色通过公共变量切换，不在组件内分散判断主题；
- 浅色窗口使用白色抬升面和较浅遮罩；
- 深色窗口使用现有深灰抬升面和较深遮罩；
- 两种主题的正文、状态色和焦点轮廓都必须保持可读对比度。

## 14. 多语言布局

- 所有业务文案通过现有 `WorkbenchLanguagePreference` 的 `zh-CN`、`zh-TW`、`en` 映射提供；
- 组件只接收已本地化文案，不在通用组件中判断语言；
- 标题、正文、后果说明和按钮允许自然换行，不使用固定文本高度；
- 英文按钮较长时操作区允许换行，但保持右对齐；
- 窗口宽度为 `min(460px, calc(100vw - 48px))`，小于 `520px` 的视口将边距缩至 `12px`。

## 15. 无障碍与焦点

- 确认窗口使用 `role="alertdialog"` 和 `aria-modal="true"`；
- 标题通过 `aria-labelledby` 关联；
- 正文和后果说明通过 `aria-describedby` 关联；
- 装饰图标标记为 `aria-hidden`；
- 焦点必须困在当前模态窗口中；
- 关闭后焦点返回原触发控件；
- 键盘焦点始终有可见轮廓；
- 不依赖颜色单独传递危险或警告语义。
