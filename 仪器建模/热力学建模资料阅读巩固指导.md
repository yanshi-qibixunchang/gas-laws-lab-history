# 热力学建模资料阅读巩固指导

用途：当后续需要恢复或维护本次热力学/硬球比热容比实验建模记忆时，指定阅读本文件，并按本文件重新阅读 `<project-root>\仪器建模` 下的资料。

## 一、先明确当前项目技术路线

阅读资料前，先固定以下结论，避免把资料中的“空气比热容比仪器”误读成最终实验物理对象：

1. 当前项目要做的是 `heatCapacity` 硬球比热容比实验。
2. 实验对象固定为单原子硬球气体。
3. 理论值为 `gamma = 5 / 3`。
4. 三维仪器模型只做教学可视化和交互载体。
5. `p0 / p1 / p2 / gamma` 不从 3D 模型计算。
6. 实验状态机是唯一数据源。
7. 3D 模型只读取状态机并展示状态。
8. 第一阶段先做程序化可运行骨架，再做 GLB 外观替换。
9. 程序化骨架定义节点名、坐标关系、pivot、hitbox 和状态绑定。
10. 后续 GLB 必须服从程序化骨架的契约。

推荐技术栈：

- `three`
- `@react-three/fiber`
- `@react-three/drei`

暂不使用：

- `react-three-rapier`
- 复杂真实物理引擎
- 一开始就制作精细 GLB

## 二、资料阅读顺序

按下面顺序读，不要先看图片就直接下结论。

### 1. 先读总说明

文件：

`<project-root>\仪器建模\简化建模版实验仪器内容说明.md`

阅读重点：

- 第一批建模只保留“集气瓶/贮气瓶”和“电子测量主机/仪表箱”两个主体。
- 真实仪器资料主要作为视觉参考，不是最终硬球实验的物理计算来源。
- 第一批不画外部导线、气管、打气球、后方支架、侧边把手。
- 保留透明方形压力瓶、顶部玻璃旋塞、瓶内杆状传感器、仪表箱数字屏、压力表、电源开关等识别结构。
- 主动删除面板上的“打气控制”拨杆。
- 参考图中的“打气控制”拨杆属于早期初稿遗留，正式建模时去掉，并缩短仪表箱横向长度。

### 2. 再读顶部玻璃旋塞说明

文件：

`<project-root>\仪器建模\特别注意-活塞模型理解\顶部玻璃旋塞说明.md`

阅读重点：

- 顶部所谓“活塞”应理解为玻璃旋塞 / 玻璃活塞阀，即 `glass stopcock`。
- 它不是上下推动式活塞。
- 它通过旋转内部孔道控制瓶内空气与外界通气或断气。
- 建模时要表现为横向透明玻璃管、向下接口、可旋转小玻璃把手。
- 这是第一阶段最重要的交互结构之一，后续应有稳定 pivot 和 hitbox。

### 3. 再读 PDF 仿真说明

文件：

`<project-root>\仪器建模\FD-NCD-C空气比热容比实验仿真使用说明.pdf`

阅读方式：

- 优先用 `pdftotext -layout -enc UTF-8` 提取文字。
- 必要时用 `pdftoppm` 渲染前几页，确认表格和版式。
- 不要把 PDF 当普通文本直接 `Get-Content`，会出现乱码和巨大二进制输出。

推荐 PowerShell 命令：

```powershell
pdftotext -layout -enc UTF-8 "<project-root>\仪器建模\FD-NCD-C空气比热容比实验仿真使用说明.pdf" -
```

阅读重点：

- PDF 给出的是仿真程序流程、状态机、读数含义、计算公式和教学提示。
- 左屏是温度信号 `U_T / mV`，中屏是压强信号 `U_p / mV`。
- 不要直接把 mV 标成摄氏度或 kPa。
- 空气仪器的实验流程可作为交互流程参考，但最终物理对象要改成硬球气体。
- 状态机思路可复用：通电、连通/调零、打气升压、封闭等待、记录、快速放气、回温、计算。
- 对数公式和近似公式的教学结构可参考，但最终公式应服务于硬球比热容比实验。

## 三、阅读后必须输出的结论

每次按本指导重读后，应该至少复述以下结论：

1. 本项目最终做的是硬球比热容比实验，不是空气比热容实验。
2. 资料中的 FD-NCD-C 仪器主要提供视觉结构、交互流程和教学表达参考。
3. 3D 模型不是数据源，不计算 `p0 / p1 / p2 / gamma`。
4. 实验状态机是唯一数据源。
5. 第一阶段目标是程序化骨架，不是精细 GLB。
6. 骨架必须稳定定义节点名、坐标关系、pivot、hitbox、状态绑定。
7. GLB 后续只替换外观，必须服从骨架契约。
8. 正式建模应删除“打气控制”拨杆，并缩短仪表箱横向长度。
9. 顶部玻璃旋塞是关键交互件，应有开/关两态、明确旋转 pivot 和 hitbox。
10. 最终视觉目标是“方形玻璃压力瓶 + 外部仪表箱”的真实仪器风格教学装置。

## 四、骨架与成品模型分工

### 程序化骨架负责

- 固定整体比例和坐标系。
- 定义压力瓶、瓶口、橡皮塞、玻璃旋塞、仪表箱、显示屏、压力表、电源开关等稳定节点。
- 定义 hitbox：旋塞、电源、调零、记录、打气动作区等。
- 定义 pivot：旋塞旋转、压力表指针、开关翻转。
- 从状态机读取数据并展示。
- 做基础反馈：屏幕亮灭、数字变化、压力表指针、旋塞开关、瓶内粒子/密度/能量提示。
- 形成 GLB 替换契约。

### 最终成品模型负责

- 精细玻璃材质、倒角、厚度、透明效果。
- 更真实的玻璃旋塞和橡皮塞。
- 更完整的仪表箱面板细节。
- 更好的金属、塑料、橡胶、发光屏幕材质。
- 灯光、阴影、相机、亮暗主题适配。
- 更顺滑的教学动画。
- 外观替换，不接管实验数据。

## 五、常见误读提醒

- 不要把空气实验直接当作最终物理实验；当前实验是硬球气体。
- 不要让 3D 粒子模拟成为 `gamma` 计算来源。
- 不要因为参考图有“打气控制”拨杆就把它保留。
- 不要一开始追求精细 GLB，先稳定骨架契约。
- 不要把 mV 显示直接改成摄氏度或 kPa。
- 不要让 GLB 自带任意节点名、pivot 或坐标，导致替换时推翻程序化骨架。

## 六、后续执行建议

如果要开始编码，先做这几件事：

1. 检查当前分支应为 `codex/thermodynamics-experiments` 或后续热力学实验分支。
2. 检查是否已有 `heatCapacity` 相关模块或历史代码，避免误恢复旧问题分支的实现。
3. 先定义状态机字段和 3D 视图 props。
4. 再建立程序化模型节点和 hitbox。
5. 用最小可运行 3D 场景验证：能显示、能交互、能读状态、不卡死。
6. 再逐步加仪器外观细节。
