# Piston Free persistence fixtures

These fixtures contain only synthetic data generated by historical pure Node
domain models, file codecs, and the production persistence facade. No desktop
application or user storage is involved. Each JSON keeps the original complete
generation and its content fingerprint.

- `pistonLegacyFreeV640.json`: released v6.4.0, commit
  `b7c81778516b90ca28c20681b1dcf2c1ca3f07d2`, Free schema 8.
- `pistonLegacyFreeV9.json`: commit
  `bd231f5fe264a7f1a1e2cac76e15ec03e0d41b96`, Free schema 9.

Both sources support only Real / Air Free experiments. Schema 9 rejects Ideal
groups during normalization and its material factory rejects helium. The
scheme/gas selection events arrived with Free schema 10.

Each generation includes an empty file; a file with frozen parameters, a saved
measurement, an excluded attempt and an acquisition candidate; and a file with
three measured periods plus completed historical fitting and calculation.
All identities and timestamps are fixed, and the waveform is specified in the
JSON provenance. The old source codec must decode each generated file as exact.

The separate `answerCases` use those same old models and codecs to capture
15 additional processing states per source: pre-fit sessions with empty or
partial point selection, empty and invalid submissions,
numeric and precision errors, mixed batch results, successful retries, revealed
answers with and without a valid attempt, and synthesized unknown history.
These cases preserve the original generation and reuse its synthetic raw data.
Correct answers cannot be edited or submitted again in either old model.

The separate `fitCases` capture the old OLS algorithm's real negative R²
roundoff (`-Number.EPSILON`) from periods 0.041, 0.055 and 0.043 seconds.
Each case includes its waveform formula and an exact old-codec file. This
boundary is accepted only when the original points reproduce all three saved
OLS outputs exactly; changing the negative R², slope or intercept is rejected.

To regenerate from the repository root with Git, Node 24 and the Windows `tar`
utility, extract only the tracked source and test helper into task-local output:

```powershell
New-Item -ItemType Directory -Force 'output/piston-legacy-fixtures/v640', 'output/piston-legacy-fixtures/v9' | Out-Null
git archive --format=tar --output=output/piston-legacy-fixtures/v640.tar b7c81778516b90ca28c20681b1dcf2c1ca3f07d2 src package.json tests/pistonOscillation/helpers/pistonOscillationCurrentRecordTestFactory.ts
git archive --format=tar --output=output/piston-legacy-fixtures/v9.tar bd231f5fe264a7f1a1e2cac76e15ec03e0d41b96 src package.json tests/pistonOscillation/helpers/pistonOscillationCurrentRecordTestFactory.ts
tar -xf output/piston-legacy-fixtures/v640.tar -C output/piston-legacy-fixtures/v640
tar -xf output/piston-legacy-fixtures/v9.tar -C output/piston-legacy-fixtures/v9
node tests/workbench/fixtures/generatePistonLegacyFreeFixtures.mjs output/piston-legacy-fixtures/v640 tests/workbench/fixtures/pistonLegacyFreeV640.json b7c81778516b90ca28c20681b1dcf2c1ca3f07d2
node tests/workbench/fixtures/generatePistonLegacyFreeFixtures.mjs output/piston-legacy-fixtures/v9 tests/workbench/fixtures/pistonLegacyFreeV9.json bd231f5fe264a7f1a1e2cac76e15ec03e0d41b96
npm.cmd test -- tests/workbench/workbenchPersistenceV3PistonLegacyFree.test.ts
```

The regression permits only the named 8/9 to 10 schema changes. Historical
period results retain their original endpoint/period answer evidence; their
versioned squared value follows the current decimal rounding contract. Named
obsolete fitting and calculation algorithms reset to point selection. Unknown
versions, unrecognized fields and altered unrelated authority remain isolated.
Answer checks compare recorded input, outcomes, flags, resolutions, feedback and
batch relationships. They do not regrade historical answers or restore an old
numeric tolerance.
